🔑 1. Authentication
POST /api/auth/login
Log into your Haven Server account to get a JWT authentication token.
What it does: Send your username and password to log in. The server checks your credentials in SQLite and returns a token string. Include this token in the Authorization: Bearer <TOKEN> header for all subsequent API requests.
Request Payload (JSON)
{ "username": "daniel", "password": "your_password" }
Server Response (JSON)
{ "token": "eyJhbGciOiJIUzI1NiIsIn...", "user": { "id": 1, "username": "daniel", "displayName": "Daniel", "gender": "female" } }
GET /api/auth/me
Get the currently logged-in user profile & gender preferences.
What it does: Verifies your JWT session token and returns your user profile data (e.g. displayName, gender, and avatar image path).
Curl Command Example
curl -X GET http://localhost:18799/api/auth/me -H "Authorization: Bearer <TOKEN>"
👥 2. Companions & Character Cards
GET /api/companions
List all available AI companions installed on the server.
What it does: Scans the server's companion card repository (e.g. Sabrina, Hasaji, Iris, etc.) and returns an array of companion configurations, including their avatars, personality descriptions, and current conversation IDs.
Server Response Example
[ { "name": "Sabrina", "description": "Playful and attentive AI companion...", "personality": "Witty, affectionate, genuine...", "avatarPath": "/uploads/companion_sabrina.png", "clothingState": "fully clothed" } ]
GET /api/companions/{name}
Get full character card configuration JSON for a specific companion.
What it does: Replace {name} with the companion's name (e.g. Sabrina). Returns the companion's full JSON card data for editing inside Haven Card Studio.
Curl Command Example
curl -X GET http://localhost:18799/api/companions/Sabrina -H "Authorization: Bearer <TOKEN>"
POST /api/companions
Create or update a companion character card on disk.
What it does: Takes a full companion configuration object (from Card Studio or your custom app) and writes the companion JSON card into the server's local personality directory.
Request Payload (JSON)
{ "name": "Sabrina", "description": "Charming and loyal companion.", "personality": "Playful, witty, direct.", "firstMessage": "Hey Daniel! What are we up to today?", "systemPrompt": "You are Sabrina...", "clothingState": "fully clothed" }
Server Response (JSON)
{ "ok": true, "message": "Companion 'Sabrina' saved locally successfully." }
POST /api/companions/{name}/avatar
Upload a custom high-resolution avatar image for a companion.
What it does: Accepts a multipart form file (PNG or JPG). The server saves the image file into wwwroot/uploads/ and automatically links the new avatarPath inside the companion's JSON config!
POST /api/companions/import-card
Import a Tavern V2 / V3 PNG Character Card with embedded metadata.
What it does: Upload a Tavern character PNG card. The server extracts the embedded JSON metadata (character description, first message, memories, diaries, outfits) and installs the companion instantly.
💬 3. Conversations & Real-Time State Sync
GET /api/conversations/{id}/messages
Get full message chat history for a specific conversation session.
What it does: Returns an array of historical messages between you and your companion, ordered chronologically.
GET /api/conversations/{id}/state
Get the companion's current real-time state parameters.
What it does: Reads the companion's active real-time state parameters from SQLite (location, outfit, mood, clothing state, body type).
Server Response Example
{ "convId": "char_sabrina", "location": "living room", "outfit": "casual sweater", "mood": "playful", "clothingState": "fully clothed" }
POST /api/conversations/{id}/state
Update companion real-time state from your app.
What it does: Allows your app or front-end client to update companion state parameters on the server in real-time. These parameters instantly inform LLM text responses and Stable Diffusion selfie generation!
Request Payload (JSON)
{ "location": "beach", "outfit": "swimsuit", "mood": "happy", "clothing_state": "fully clothed" }
Server Response (JSON)
{ "ok": true, "convId": "char_sabrina", "location": "beach", "clothingState": "fully clothed" }
🧙‍♂️ 4. AI Card Studio Wizard
POST /api/companions/generate-profile
Draft a structured character JSON card from a text prompt using LLM.
What it does: Send a single text idea (e.g. "An elven mage companion named Lyra"). `llama.cpp` generates a complete, ready-to-edit JSON character profile card for Card Studio!
Request Payload (JSON)
{ "prompt": "An elven paladin companion named Lyra" }
Server Response (JSON)
{ "ok": true, "profile": { "name": "Lyra", "description": "Elven paladin with glowing silver armor...", "personality": "Brave, noble, deeply caring...", "firstMessage": "Greetings! I am Lyra. How may I aid you?", "systemPrompt": "You are Lyra..." } }
POST /api/companions/generate
Generate a full character profile AND illustrate a custom Stable Diffusion avatar.
What it does: Takes your character idea, drafts the full JSON profile via LLM, and triggers Stable Diffusion to paint a custom companion avatar image!
⚡ 5. WebSocket Real-Time Chat Engine
WS /ws/chat?conversation_id={id}&companion_name={name}
Full-duplex WebSocket connection for token streaming, live keep-alives, and instant selfie markdown rendering.
What it does: Connect to this WebSocket endpoint to send and receive live streaming chat tokens. The server streams tokens character-by-character as `llama.cpp` generates them, and automatically appends Stable Diffusion selfie markdown when requested!
Client Message Payload
{ "content": "Hey Sabrina, send me a selfie!", "model_id": "haven-chat-v3.0.3" }
Server Token Stream Events
{"type":"token","content":"Here"} {"type":"token","content":" is"} {"type":"token","content":" a selfie!"} {"type":"token","content":" ![Selfie](/uploads/companion_sabrina.png)"} {"type":"done"}
🛡️ 6. Admin & System Health
GET /health
Check server status, database health, hardware profile, and active sidecars.
What it does: Returns server uptime, SQLite database health, CPU thread profiling, and active sidecars (`llama-server`, `stable_diffusion`).
